# 노트별 점수 계산

`liveScore.js`는 형제 프로젝트 `prsk-score-calc/src/index.js`의 동일한 스냅샷이다. 수식 수정은 원본에서 하고 이 파일 및 백엔드 `sekai-statics_local/scripts/lib/live_score/index.mjs`를 함께 갱신한다. 별도 npm 의존성은 없다.

`../utils/noteScore.worker.js`가 `asset.rilaksekai.com/data/live-score/rules.json`과 `charts/{musicId}-{difficulty}.json`을 읽는다. 서버의 `generate_music_metas.py`가 같은 SUS와 마스터에서 이 입력을 생성한다. 노트 시각·종류는 손실 없이 유지한다. `REACT_APP_ASSET_BASE_URL`을 지정하면 그 주소를 사용한다.

`/event` 주요 정보의 로앤 하드(226-hard), 엔비 익스(74-expert)는 `public/live-score/charts/`의 채보와 `public/live-score/rules.json`을 사용해 노트별로 누적한다. 이 두 채보는 외부 CDN을 요청하지 않는다. 공개 데이터 생성 시 이 세 파일도 같은 산출물로 갱신한다. 1픽은 기본 OFF이고 스킬/피버 지연은 기본 200ms이다. 입력을 비워두면 200ms를 적용하고 두 구간의 시작·끝을 같은 만큼 이동한다. 1픽 ON이면 저장된 입력값을 유지한 채 지연을 0으로 계산한다. 이 설정은 주요 정보의 로앤파/엔비 멀티 계산에 적용한다. 이벤트 보정값은 기존 메타의 `event_rate`를 사용한다. `/chall`은 150개 후보를 현재 덱의 메타 점수로 다시 비교해 상위 100개만 표시하며, 검색곡/현재 페이지부터 노트별로 순차 계산한다. 점수 갱신으로 행이 이동하지 않게 메타 정렬은 유지한다. 스킬 순서 직접 변경도 Worker에서 노트별로 계산한다.

기본 스킬 구간은 시작 포함·종료 제외다. 밀어넣기를 켜면 솔로·멀티에서 지속시간에 실용 여유시간 65ms을 더한다. 시작점이 롱노트 구간(시작·끝 포함)이면 절반(32.5ms)만 더하고, 앙코르는 원래 리더의 스킬을 사용한다. 최저/최고는 중복을 제외한 최대 120가지 순서를 실제 누적해 구한다. 계수는 스킬 비중 그림에만 사용한다.

Worker 작업은 한 번에 하나, 채보 캐시는 최대 192개, 결과는 최대 512개다. 입력 변경 시 이전 요청 결과를 버리고 새 요청을 계산하며, 페이지 이동 시 남은 작업의 우선순위를 바꾼다. 추천 150개 채보는 `challenge-top.json`으로 한 번에 받는다. 묶음은 밀어넣기 OFF/ON 추천의 합집합과 판정 규칙을 담고, 메모리에 원본을 보관한 뒤 사용 시 준비한다. 묶음 밖 채보나 묶음 로드 실패 시 개별 주소로 폴백한다. 네트워크 요청은 15초 제한을 두고 채보 로드 실패를 표시한다. 메타로 임시 표시하는 동안에는 이를 점수 옆에 표시한다.

챌라는 덱을 변경할 때 밀어넣기 OFF/ON 각각의 메타 상위 100개를 준비하고, 두 목록의 합집합만 Worker에서 두 가지 조건으로 미리 계산한다. 체크 전환은 저장된 결과를 선택하며 다운로드·계산을 재시작하지 않는다. 스킬 순서 아래 추가 점수는 표시 중인 순서를 고정하고 해당 발동 하나만 연장한 결과에서 미적용 점수를 뺀 값이다. 앙코르도 따로 계산하며, 전체 밀어넣기 점수는 별도로 노트별 누적하므로 반올림·구간 중첩에 따라 각 증가분 합계와 다를 수 있다.
